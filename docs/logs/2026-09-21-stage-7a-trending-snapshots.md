## 做了什么

Trending 原来只有"即时展示"：刷新一次就覆盖，看不出排名变化，也看不出谁是新上榜的。这一版把它变成可对比的本地历史。

### 快照与派生（纯函数）

`src/types/trendingSnapshot.ts` + `src/utils/trendingSnapshots.ts`：

- 按「周期 × 语言 × 自然日」存快照：**同一天刷新多次只保留最后一份**，否则用户每次刷新都会看到"上升 N 名"的假象。
- 每个桶最多 30 份、超过 90 天的快照在写入时清掉；坏输入（缺 period、时间戳不可解析、空榜单）返回 null 而不是抛错。
- `buildTrendingHistory` 给出：当前名次、上一天名次、名次变化、首次上榜时间、连续上榜天数、自首次记录以来的 star 增量。名次变化对比的是**上一天**，不是"上一份"。
- `pickTrendingHighlights` 挑出上升 / 下降 / 新上榜，供界面展示。

### 采集与展示

- `useTrendingSnapshotCapture`：只在 trending 频道把当前可见榜单记成快照，接口没给 `rank` 时用当前顺序兜底。去重与上限在 store 侧的纯函数里，重复渲染不会堆出矛盾历史。
- `TrendingHistoryPanel`：榜单上方的小块「榜单变化」。**只有一份快照时不渲染**——那时所有条目都会被算成"新上榜"，没有信息量。
- 口径写在界面上：名次变化标注"与上一天的本地记录相比"；star 增量写成"自首次记录新增 N stars"，**不冒充 GitHub 的"本周期新增"**（我们只能从自己的两次记录做差）。

### 商店

`trendingSnapshots` 进唯一持久化 Store，版本 16 → 17。normalizer 与 migrate 共用同一份校验：坏快照与超期记录在迁移阶段就被丢弃。

8 个新 key，十种语言一次补齐。

## 过程中踩到并修掉的两件事

1. **zh-TW 又踩"与简体同形"**：`上升`/`下降` 两个词在繁体里写法相同，`check-i18n.cjs` 判为照抄简体。改成台湾常用说法「爬升 / 下滑」。这类词（小/中/大、上升/下降）在中文里天然同形，写 zh-TW 时要主动换一个说法。
2. **并集合并把 DiscoveryView 的 JSX 弄乱了**：新面板被塞进了列表条件表达式的开头，typecheck 直接报语法错。手工重排为"面板在前、列表在后"。这是这一系列合并里第三次在 JSX 上翻车——并集策略对"两边各自往同一处塞 JSX 子节点"是无效的，必须人工确认。
